## 3. Suggested update body

```text
Two things in this release, and neither of them changes how conversion works.
Profiles generated by v1.1.0 are byte-identical to v1.0.0.

NO DOWNLOAD NEEDED ANYMORE

There is now a browser version:
https://la-dosette.github.io/PrusaToOrca/

Drop your .ini, get your .orca_printer. Nothing is installed and nothing is
uploaded — the conversion runs on your own machine, in the tab. It runs the
project's own convert.py compiled to WebAssembly, so it is not a rewrite that
could behave differently: it is the same converter, and it produces identical
output.

The desktop app still does more: custom key mappings, the guided import
assistant, automatic backups, conversion history, bug reports and the
multilingual interface.

ABOUT THE VIRUSTOTAL REPORT

A user posted a VirusTotal scan showing 6 of 70 engines flagging the v1.0.0
executable. That report was accurate, and it was a false positive. Rather than
just say so, here is the detail.

All six detections were generic machine-learning verdicts —
Trojan:Win32/Wacatac.B!ml (the "!ml" suffix means machine learning),
"Static AI - Suspicious PE", "BehavesLike.Win64.Dropper", and two bare
"MALICIOUS" results. Not one engine named an actual malware family, and no
signature-based engine — Kaspersky, ESET, Bitdefender, Avast, Sophos, Trend
Micro, F-Secure — flagged anything.

The cause was how I packaged it. v1.0.0 was a PyInstaller "one-file" build,
which embeds a compressed payload, unpacks it into %TEMP% when you launch it,
and runs a second executable from there. That is behaviourally identical to a
dropper, which is exactly why "dropper" was the reported threat label.

What changed in v1.1.0:

- No more one-file build. The app is now a normal folder in a .zip. Nothing
  self-extracts. The launcher went from 15.6 MB to 2.3 MB.
- UPX compression disabled — another heuristic trigger.
- Proper version metadata embedded, so the executable identifies its publisher,
  product and version instead of being anonymous.
- Releases are built by GitHub Actions on a clean machine, not mine.
- Every release ships a SHA-256 checksum and a signed build provenance
  attestation.

That last one is the real answer. You no longer have to trust my word or argue
with a scanner — you can verify that the binary was built from the published
source:

  gh attestation verify PrusaToOrca-v1.1.0-windows.zip --repo La-Dosette/PrusaToOrca

Full write-up:
https://github.com/La-Dosette/PrusaToOrca/blob/main/SECURITY.md

WHAT THE APP ACTUALLY DOES ON YOUR MACHINE

Reads the .ini files you select. Writes the bundle where you tell it to. It
makes exactly one network request, and only when you click "Check for updates",
to read the latest release tag from api.github.com. No telemetry, no uploads,
no background activity. The source is public, so you can check all of this
yourself.

ALSO FIXED

The in-app update check was comparing the release tag against a hardcoded
version number that never matched, so a fresh install would tell you an update
was available forever. Fixed.

As always: back up your OrcaSlicer profiles before importing anything.
```
