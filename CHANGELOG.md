# Changelog

## v1.1.0

Packaging and distribution release. No conversion behaviour changes: profiles
generated by this version are byte-identical to v1.0.0.

### Antivirus false positives

v1.0.0 was flagged by 6 of 70 engines on VirusTotal. All six were generic
machine-learning verdicts with no named malware family, and no signature-based
engine detected anything. The cause was the packaging, not the code.

- Switched from a PyInstaller one-file build to a folder shipped as a `.zip`.
  The one-file build unpacked itself into `%TEMP%` at launch and executed a
  second binary from there, which is what a dropper does. The launcher drops
  from 15.6 MB to 2.3 MB and nothing self-extracts.
- Disabled UPX compression, which is a heuristic trigger on its own.
- Embedded a version resource, so the executable reports its publisher, product
  and version to Windows instead of being anonymous.

### Verifiable releases

- Release builds are produced by GitHub Actions on a clean runner. Nothing you
  download is built on a maintainer's machine.
- Every release carries a signed build provenance attestation. Verify with
  `gh attestation verify <zip> --repo La-Dosette/PrusaToOrca`.
- Every release ships a `SHA256SUMS.txt`.
- `PrusaToOrca.spec`, the build recipe, is now tracked in the repository.

### Web version

- Added a browser version at https://la-dosette.github.io/PrusaToOrca/ that
  converts a bundle with no install and no upload. It runs the project's own
  `convert.py` compiled to WebAssembly, so it cannot drift from the desktop app,
  and its output is byte-identical.
- Desktop-only features remain: custom key mappings, the guided import
  assistant, backups, conversion history, bug reports and the multilingual
  interface.

### Fixed

- The in-app update check compared the release tag against a hardcoded
  `APP_VERSION` of `0.2.0` while release v1.0.0 shipped an asset named
  `PrusaToOrca-v0.2.0.exe`. A fresh install permanently reported that an update
  was available. `version.py` is now the single source of truth and the release
  workflow refuses to publish when the git tag disagrees with it.
